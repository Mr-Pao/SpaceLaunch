## 二、P0 —— 阻断级（必须修，5 分钟可解）

### P0-1 · `search.vue` 机构搜索引用未定义函数 `hit`，搜索"机构"必崩
- **文件**：`pages/search/search.vue` 第 182 行
- **现象**：`runSearch()` 拼接"机构"分组时调用 `hit(x.name, kw) || hit(x.abbrev, kw) || hit(x.nameZh, kw)`，但整个文件**从未定义 `hit`**（只有 `launchHit`/`rocketMatch`/`launchRow`）。只要 `d.agencies` 非空，filter 回调抛 `ReferenceError`，`this.groups = groups` 永不执行，搜索结果不渲染、Promise reject。
- **证据**：`const ag = d.agencies.filter((x) => hit(x.name, kw) || ...)` —— `hit` 全文件无定义。
- **根因**：`verify-pure.js` 只覆盖了发射/火箭分支，机构分支漏测，假绿掩盖。
- **修复**：
  ```js
  const hit = (field, k) => (field || '').toLowerCase().indexOf(k) !== -1
  ```
  并在 `verify-pure.js` 补一条机构分支用例。

## 三、P1 —— 重要级（建议下次发版前修）

### P1-1 · `gallery-all.vue` 违反安全区约定（安卓底部内容被压）
- **文件**：`pages/gallery-all/gallery-all.vue` 第 184 行
- **现象**：`padding-bottom: calc(60rpx + env(safe-area-inset-bottom))` 缺少裸值/`constant()` 兜底，旧安卓内核不识别整条 `calc` 会整体失效，iPhone Home 条压住"已到底·共 N 张"。
- **修复**：补两行
  ```css
  padding-bottom: 60rpx;
  padding-bottom: calc(60rpx + constant(safe-area-inset-bottom));
  padding-bottom: calc(60rpx + env(safe-area-inset-bottom));
  ```

### P1-2 · `station.vue` / `expedition.vue` 对可能缺失的数组直接取 `.length`，后端缺字段即渲染崩溃
- **文件**：`pages/station/station.vue` 第 53/66/92 行（`station.crew.length` 等）；`pages/expedition/expedition.vue` 第 28/43 行
- **现象**：`station`/`exp` 初始为 `{}`，但这些 `.length` 访问发生在 `v-else` 分支内，依赖后端 JSON 一定带 `crew`/`expeditions`/`owners`/`patches`。历史快照或部分空间站无 crew 时模板求值抛 `TypeError`。
- **对照**：`astronaut.vue` 已用 `(this.a && this.a.missions) || []` 守卫，这两页是漏网的异常分支。
- **修复**：`data()` 给默认空数组，或模板改 `(station.crew || []).length`。顺手把三页重复的 `statusZh` / `dayOf` 抽到 `utils/format.js`（见 P2-1/2）。

### P1-3 · `countdown.vue` 缺 `watch net`，异步数据下倒计时永不开表
- **文件**：`components/countdown/countdown.vue` 第 69–88 行（`mounted` 调 `start()`）
- **现象**：父组件常先以 `net=''` 渲染（COS 异步拉数据），`mounted` 时 `ended` 为 true，`start()` 直接 `return` 不启定时器；之后 `net` 更新，但**无 `watch net`**，`start()` 不再被调，倒计时永久停在"时间已到"。被首页/发射卡片等多处复用，影响面大。
- **修复**：加 `watch: { net() { this.start() } }`（start 内部已 `stop()` 防重）。

### P1-4 · `launch-detail.vue` 滚动形变被空 `setScroll(){}` 架空（死代码 + 约定矛盾）
- **文件**：`components/launch-detail/launch-detail.vue`（看图态 `photo` 分支）
- **现象**：`st` 永远为 0，整套 `p`/`fillOpacity`/`barOpacity`/`range` 成为死代码；且与"看图态恒满屏不随滚动收缩"的设计自相矛盾（之前已删上拉形变逻辑，但壳层 `onPageScroll` 仍转发、组件里 `setScroll` 成了空函数）。是脆弱的隐式耦合。
- **修复**：要么彻底移除 `setScroll`/相关 computed（推荐，看图器已不依赖形变），要么补真实实现。顺带清理该组件约 10 处死 CSS/死方法（P2-9）。

### P1-5 · `sync.js` `pruneStaleUpcoming` 读取 previous 失败时误删全部陈旧项
- **文件**：`scripts/sync.js` 第 186–225 行
- **现象**：先读 `launches-previous.json` 当"真实终态"，用的是**非 200 即抛**的 `readCosJson`。一旦该读取瞬态失败（5xx/CDN 抖动），`prev` 为空，循环走 `else` 对每个"Go/In Flight 且超 3h"项 `drop.add()`，`splice` 把**所有**陈旧 upcoming 整体删除。下一轮 previous 恢复也补不回，upcoming 列表出现空档。
- **修复**：`catch` 里置 `prevFailed = true`，循环内 `if (prevFailed) return;`（整体放弃本轮 prune，保留全部）。

### P1-6 · `aggregate.js` 亚轨道统计恒为 0，且被"假绿"单测掩盖
- **文件**：`scripts/lib/aggregate.js` 第 102 行；`scripts/verify-pure.js` 夹具用 `'Sub'`
- **现象**：`if (f.orbit === 'Sub') row.sub++`，但 LL2 真实值为 `"Suborbital"`，**永远不等** → `sub` 恒为 0，`orbital(=total-sub)` 虚高。统计页"亚轨道"维度永远空。更隐蔽的是 `verify-pure.js` 的夹具喂的是 `'Sub'`，测试通过却掩盖了真实数据不匹配。
- **修复**：`String(f.orbit).toLowerCase().includes('sub')`；同步把 `verify-pure.js` 夹具改成真实值 `'Suborbital'`。

## 四、P2 —— 优化建议（可排期，不阻塞发版）

### 数据层 / utils
- **P2-1** `list-mixin.js` 第 15/24 行 `set.has(item.id)` 未 `String()`：favorites 模块自身约定所有 id 用 `String()`，但 mixin 直接用 `set.has(item.id)`。发射 id 是 UUID 字符串恰好不踩；一旦复用到**数字 id** 的火箭/活动收藏，字符串/数字不匹配会使收藏标记、置顶**静默失效、不报错**。改 `set.has(String(item.id))` 即可（2 行，零副作用）。
- **P2-2** `format.js` 第 440 行 `rocketByPrefix` 每次调用都 `Object.keys(ROCKET_ZH).sort(...)`：高频路径（搜索/列表渲染）上的无谓重复排序，提到模块顶层只算一次。
- **P2-3** `format.js` `massText` 与火箭详情页 `mass()` 逻辑重复（注释自承），收敛到一处。
- **P2-4** `custom-tab-bar/index.js` 与 `utils/config.js` 各实现一份版本判定规则（当前对拍一致，但属拷贝式重复，任一边改漏同步就分叉）。建议抽纯函数共用，并强制 CI 跑 `verify-config.js`。
- **P2-5** `format.js` `countryOf` 第 878–887 行：未命中国家名时末段硬截断，偶发奇怪 chip；可优先跑 `placeZh` 兜底。
- **P2-6** DATA_VERSION 注释/文档漂移：`utils/data.js:172` 注释写"v13.1"实际是 `v14.1`；`README.md` 仍写 DATA_VERSION=8。误导后续维护者。

### 页面层
- **P2-7** 多处重复"状态→中文"映射：`stations/station/expedition/astronaut` 各写一份 `statusZh`、`dayOf`（`ISO→中文日期`）、简介折叠逻辑（`descText + descOver>120`）。抽到 `utils/format.js` 统一。
- **P2-8** `rocket.vue` / `pad.vue` 在 `onLoad` 与 `onShow` 双调 `getConfig`（冗余）；`search.vue` 模块级 `cache` 跨实例共享、无失效判断。
- **P2-9** `launch-detail.vue` 约 2844 行单文件，含约 10 处死 CSS/死方法/死事件，建议拆分（内容/看图器/状态条各自成块）。
- **P2-10** `media.vue` 图片按奇偶索引硬分两列，等宽不等高导致列高失衡；建议按"当前较矮列"追加或预存高宽比。
- **P2-11** 魔法数字散落：导航栏变实色阈值（180/160/120）、折叠阈值 120、列表 STEP=12 等，建议定义为语义常量（如 `NAV_SOLID_SCROLL`、`DESC_FOLD`）。

### 数据管道 / scripts
- **P2-12** `videos.js:179` / `timeline.js:213` 硬编码 `v: 13`，与 DATA_VERSION=14 失配，每次加载视频/时间线都刷"版本不一致"告警，且脱离版本哨兵。建议引用 `DATA_VERSION` 并把这两文件纳入 `verify-pure.js` 对拍。
- **P2-13** `slim.js` 第 157 行 `vid` 字段读 `l.vid_urls || l.mission.vid_urls`，normal 模式下两者均 undefined → `vid` 恒为 `[]`（死字段 + 误导性注释）。删字段或改注释。
- **P2-14** `fetch.js` 主数据集 LL2 抓取默认不重试 429（仅 dockings opt-in）。同小时多 cron 漂移（archive 12 + images 7 + timeline 8 + 常规）易超 15 次/小时配额，单点 429 即整数据集当轮不更新。建议统一加 429 指数退避。
- **P2-15** `slim.js` 第 398–399 行 `geo_capacity` / `sso_capacity` 字段名存疑（LL2 2.3.0 标准字段多为 leo/gto），可能恒为 null 且前端无"暂无"兜底。需抓一条 detailed 响应核对 schema。
- **P2-16** 分页游标/重试逻辑在 `images/videos/archive/timeline` 四处各写一份（魔法数字 `PER_RUN`/`PAGE`/`KEEP` 口径不一）。建议抽公共 `paginateLL2()`。
- **P2-17** 同名 `readCosJson` 双语义：`lib/cos.js`（404→null，增量用）vs `sync.js`（非 200 抛，强依赖用）。易误用导致"覆盖清空线上数据"灾难。建议统一为 `readCosJson(key, {notFoundIsNull})` 带选项。
- **P2-18** `fetch.js` 第 47–54 行非 200 / JSON.parse 失败时未 `res.resume()` 消费响应体，高并发/重试密集可能泄漏连接。
