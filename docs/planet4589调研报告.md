# planet4589 GCAT 内容调研报告

- **调研时间**：2026-10-27 23:09（用户睡前触发，只读调研，未改动代码）
- **目标站点**：https://planet4589.org/space/gcat/ （Jonathan McDowell 的 GCAT — General Catalog of Artificial Space Objects）
- **结论先行**：GCAT 有**高价值、且与现有 LL2 数据源互补**的内容（尤其是航天器/卫星编目），可作为小程序的差异化新模块；但接入需新写解析+CI 管道，且数据更新节奏（季度级）与小程序「实时发射」定位不同，建议**先做一个轻量「航天器/卫星百科」试水**，而非大举接入。

---

## 一、GCAT 是什么

- 作者 Jonathan McDowell（哈佛天体物理学家，国际宇航科学院），是航天编目领域的权威数据源，也是 *Jonathan's Space Report* 的底层数据库。
- **授权：CC-BY**（署名即可商用），引用格式 `data from GCAT (J. McDowell, planet4589.org/space/gcat)`。小程序内加一处「数据：GCAT」出处标注即可合规。
- 当前版本 GCAT Release 1.8.8 (2026-09-03)，数据更新 2026-10-25。
- **数据模型**：人工空间物体（object，卫星/火箭体/碎片/残骸）→ 状态/阶段（phase）→ 关联发射（launch）→ 关联组织（机构/国家/所有者/制造商）。覆盖 1957 年至今。

| 数据集 | 内容 | 格式 | 与现有 LL2 重叠度 | 小程序价值 |

## 三、逐项评估

### 1. Satcat 卫星/航天器编目 —— 最值得做（差异化）
- **为什么有价值**：小程序现有数据来自 LL2，强项是「发射事件」（何时、何箭、何任务），但**弱在「航天器本体」的编目**——在轨卫星有多少、谁发射的、什么轨道、现在什么状态，LL2 基本没有完整库。GCAT 的 satcat 正好补这块空白。
- **可做的新页面**：「航天器/卫星百科」——按所有者（ SpaceX/NASA/各国航天局）、国家、轨道类型（LEO/GEO/SSO）、状态（在役/失效/再入）筛选浏览；点开看单星档案（编号、国际编号、发射日期、轨道参数、来源任务）。
- **契合度**：高。它把小程序从「发射追踪」延伸到「太空资产总览」，是 LL2 给不了的独家内容。

### 2. 在轨物体统计图表 —— 中（适合「探索/统计」页）
- 基于 satcat 按国家/年份/轨道聚合，做可视化（各国在轨卫星数、年度发射-入轨趋势）。小程序已有 `stats` 页，可在此叠加「全球在轨资产」视角。
- 注意：GCAT 是季度级更新，图表适合做「存量快照」而非「实时增长」。

### 3. 解体/碰撞/再入事件 —— 中（科普向）
- 火箭残骸、太空垃圾、在轨解体是大众感兴趣的科普题材，目前小程序完全没有。可作为「探索」页的轻量科普模块（时间线/事件流）。

### 4. 发射编年 / 发射场 / 机构表 —— 低（重叠，不优先）
- 与小程序现有 LL2 数据高度重叠，GCAT 在这几类上并不比 LL2 更优（甚至更新更慢）。**不建议**新建页面，最多用来做历史归档的交叉校验。

## 四、接入成本与风险

| 项 | 说明 |
|---|---|
| 数据获取 | GCAT 是 **HTML 大表 / 定宽文本文件**（非 API），需新写解析脚本（类现有 `scripts/lib/slim.js`），按字段裁剪后镜像到 COS。 |
| CI 管道 | 需在 `sync.yml` 增加数据集（或单独 workflow），定时（季度/月度）拉取解析。数据量大（satcat 上万条），要像 `gallery` 那样分片+缓存版本，避免一次拉爆前端。 |
| 存储 | 裁剪后的 satcat 子集（仅展示字段）预期数百万字节级，需评估小程序包/Storage 上限，建议只放摘要索引+详情按需拉。 |
| 授权合规 | CC-BY，必须在页面/关于里标注「数据来源：GCAT (J. McDowell)」。 |
| 更新节奏错配 | LL2 实时（小时级），GCAT 季度级。混用时需明确区分「实时发射」与「编目快照」，避免用户误以为卫星状态是实时的。 |
| 维护成本 | 多了一种外部数据源与解析器，长期要有人维护（字段变更、解析失效）。 |

## 五、与小程序定位的契合度

- **契合**：小程序名 SpaceLaunch，愿景「记录人类成为多星球物种的进程」。satcat 把视角从「一次次发射」拉到「人类在轨资产总量」，叙事层级更高，且是 LL2 给不了的独家内容。
- **偏离风险**：若大举接入解体/碎片/全部发射编年，内容会偏离「发射追踪」主线，变成「航天百科」，用户可能觉得杂。建议**从小切口（卫星编目）试水**，验证用户兴趣再扩展。

## 六、分级建议

| 优先级 | 建议 | 投入 |
|---|---|---|
| ★★★ | **新增「航天器/卫星百科」页**，数据取自 GCAT satcat 裁剪子集（所有者/国家/轨道/状态筛选，单星档案） | 中：解析脚本 + 1 个列表页 + 1 个详情页 + CI |
| ★★☆ | **探索页叠加「全球在轨资产」统计图表**（基于 satcat 聚合） | 低-中：复用 stats 页 |
| ★★☆ | **科普模块：在轨解体/再入事件流** | 低：单页时间线 |
| ★☆☆ | 发射编年/发射场/机构表 | 不优先（与 LL2 重叠） |

---

## 七、结论

GCAT **值得接入，但只接最能形成差异化的 satcat（航天器编目）**，其余数据集与现有 LL2 重叠，性价比低。接入需新建解析+CI 管道、注意 CC-BY 署名与更新节奏差异。**建议明早先就「是否做卫星百科页」做决策**，再评估具体实现排期；本期（3.2.x）可暂不动，作为下一阶段候选。

> 注：本次仅调研，未写入任何代码或数据。如决定接入，第一步应先用 `curl`/WebFetch 抓一份 `satcat.html` 样例，确认字段结构与解析可行性。
